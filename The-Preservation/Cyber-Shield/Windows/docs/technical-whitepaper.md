# 网安智盾技术白皮书

**所属体系**：民用互联网合规反制体系（CICCS）
**命途归属**：存护
**组件定位**：多举报平台接入的合规反恶俗防御与反伤软件
**版本**：V1.0
**密级**：内部公开

---

## 一、软件定位

网安智盾是一款软件，不是人工流程，不是单个平台举报入口。其核心职能是：聚合多个官方举报平台，作为存护命途的高级执行体，实现防打号、防点号、带反伤。

软件本身不生产举报通道，而是把各官方举报平台的入口编排起来，统一取证、统一装弹、统一发射。用户端零代码，普通人安装后双击运行、点确认即可完成多平台并发举报。

"多举报平台"指软件可接入并编排的官方合规举报入口集合，至少包含：中央网信办举报中心（12377）官网、网络举报客户端、12377 热线、jubao@12377.cn 邮箱、微信公众号"中央网信办举报中心"一键举报、官方微博私信举报。各地网信办举报渠道、公安部网络违法犯罪举报网站等作为扩展平台接入。

## 二、合规底座

网安智盾的全部反制行为建立在官方举报渠道之上。中央网信办（国家网信办）举报中心开通的主要渠道包括：

- 举报中心官方网站（www.12377.cn），首页设有违法和不良信息举报入口
- 官方微博和微信公众号中设置了移动端举报入口
- "网络举报"APP
- 拨打 12377 举报热线

各地网信办设有独立举报渠道，各省行政区内网站、自媒体、网络平台、新媒体账号发布的违法和不良信息由对应省网信办受理。

公安部网络违法犯罪举报网站（www.cyberpolice.cn）提供涉网络诈骗等违法犯罪的联动处置举报入口，与 12377 联动。

网安智盾的所有发射通道、弹药格式、取证规范，严格映射上述官方要求。这是软件合法性的唯一底座。

## 三、防御层架构（四层防御）

网安智盾的"盾"字，首先指防御，其次才是反伤。防御是本，反伤是末。防御做不好，反伤再猛也是事后补救。

防御的三大对象：
- **防打号**：恶意举报冻号——对方批量向平台举报你的账号，触发风控封号
- **防点号**：改包攻击——对方修改数据包绕过正常接口，直接对你的账号发起攻击（批量加好友、拉群、临时会话），不需要你同意
- **防炸群/防骚扰**：对方通过群聊、私聊、临时会话对你进行刷屏、恐吓、仿号、人肉

### 第一层：账号加固（静态防御）

账号本身的抗性提升，让对方打号和打不动。

PC端/移动端统一配置：
- 开启设备锁、登录保护、异地登录提醒
- 实名认证（提升申诉权重，降低被误杀概率）
- 绑定手机+邮箱+密保问题（多因子，提升账号权重）
- 关键账号与手机号、身份证、家庭地址脱钩，使用虚拟号/临时邮箱注册辅助账号
- 核心账号单独上备用机/模拟器，与日常设备虚拟化隔离，打断对方 IP/设备指纹追踪

上述加固项写入 config.ini，软件首次启动时检测并提醒用户未完成的项目，逐项引导完成。加固状态可视化面板常驻托盘。

### 第二层：接口封锁（动态防御·防点号核心）

点号的本质是改包攻击绕过正常接口，防御核心是收窄接口暴露面。

PC端自动封锁（软件一键执行）：
- 关闭"允许通过 QID/手机号找到我"
- 关闭"允许群聊临时会话"
- 关闭"允许陌生人邀请加入群聊"
- 关闭"允许通过附近的人/兴趣部落找到我"

频率监控与自动应急响应：
- 监测异常加好友频率（短时间内大量陌生请求→自动开启"禁止任何人添加"）
- 监测异常拉群请求（短时间内大量被拉→自动退出并拉黑发起人）
- 监测异常临时会话（大量陌生临时会话→自动冻结临时会话入口）
- 监测异常举报反馈（收到平台"你的账号被举报"通知→触发取证+反伤流程）

响应动作：上述任一阈值触发，软件在 5 秒内自动执行接口封锁，并向用户弹窗提示"检测到点号攻击，已自动封锁 X 个接口"。用户可在面板一键恢复。

### 第三层：群组与社交隔离（纵深防御）

群组管控：
- 开启验证入群
- 全员禁言（仅管理员发言）或白名单模式
- 敏感词过滤（关键词论的个人三词反向用于自身群防御）
- 群成员异常变动监控（短时间内大量陌生号加入→自动开启入群验证并踢出陌生号）

社交隔离：
- 核心账号不直接暴露在公开群，使用替身号参与公开讨论
- 替身号矩阵管理（2-3 个替身号，资料与主号相似但不完全相同，主号被冻时替身号顶上）
- 私聊敏感内容自动提醒（含手机号、身份证、地址的私聊消息→弹窗提醒用户"此消息可能泄露隐私"）

### 第四层：取证与预警（主动防御）

全时取证（常驻后台）：
- 截图自动保存（系统截图工具重定向到网安智盾 evidence 目录）
- 录屏循环缓冲（OBS Studio WebSocket 对接，保留最近 60 秒，触发攻击时自动固化前后各 30 秒）
- 聊天记录自动归档（QQ/微信漫游消息周期性拉取，存本地加密）
- 平台通知监听（QQ/微信推送→关键词触发→自动取证）

预警系统：
- 攻击发生→托盘图标变红 + 声音警报 + 手机推送（APK 端）
- 预警弹窗显示：攻击类型（打号/点号/炸群/人肉）、攻击源账号、已自动执行的封锁动作、取证完成状态
- 用户点"反伤"→进入发射流程

威胁评分：对每次攻击进行威胁评分（轻度骚扰/中度打号/重度点号/组织化进攻），评分驱动后续动作：
- 轻度→仅取证+封锁，不反伤
- 中度→取证+封锁+单平台反伤
- 重度→取证+封锁+多平台并发反伤
- 组织化→取证+封锁+多平台并发反伤+通知虚无侧全频道频带阻塞干扰+通知巡猎侧超限卫兵

## 四、功能架构

### 监测层

PC 端通过系统通知监听与窗口事件捕获，监测 QQ/微信等推送通知，关键词触发（"账号异常""批量举报""异地登录""被加好友""被拉群"等可配置）。

移动端通过 Android NotificationListenerService 监听通知。该服务属于高敏感能力，Android 要求通过专用设置页显式授权。合规约束：仅在隐私政策中明确说明通知监听目的；仅监听必要应用；不存储、不上传通知内容到外部服务器；提供关闭监听的选项；用户拒绝权限时不影响与监听无关的功能。

### 取证层

触发后自动取证：
- 截图保存（满足举报要求的样本截图）
- 录屏（保留触发前后各 30 秒，对接 OBS Studio WebSocket）
- 聊天记录导出（在用户已授权且平台允许的范围内）
- 证据归档至本地 evidence 目录，按 YYYY-MM-DD/触发类型/ 结构存放
- 生成 metadata.json 记录触发时间、攻击类型、目标账号、证据列表

取证层产出的证据包，严格对应举报要求："违法不良信息具体网址/账号名/截图、违规内容描述、发生时间、相关证据（聊天记录、视频、图片等）"。

### 装弹层

按 CICCS 标准弹药 v1 格式（个人版/群聊版）整理证据包为可发射弹药。字段包括：目标账号、时间（精确到分钟）、违规内容（原文引用）、对应举报专区类别（政治类/暴恐类/诈骗类/涉企侵权/涉未成年人/色情类/低俗类/赌博类/涉 AI 应用乱象/侵权类/谣言类/其他类）、证据附件。

装弹层不伪造证据，不夸大违规性质，严格按 12377 举报专区类别匹配。

### 发射层（多举报平台并发）

发射时按 config.ini 中启用的通道列表并发：

1. 12377 官网（www.12377.cn）：通过浏览器插件在对应举报专区自动填充表单提交
2. 网络举报 APP：APK 端唤起客户端并跳转对应举报页
3. 微信公众号"中央网信办举报中心"：APK 端唤起微信并跳转一键举报
4. 官方微博私信：预留接口跳转到移动端举报入口
5. 12377 热线：预留呼叫接口，用户点确认后拨号
6. jubao@12377.cn 邮箱：通过系统邮件客户端发送，邮件正文按官方要求附链接和截图
7. 各地网信办举报渠道：扩展平台，按目标属地启用
8. 公安部网络违法犯罪举报网站（www.cyberpolice.cn）：涉网络诈骗等违法犯罪时启用

通道健康探测：发射前先探测各通道可达性，被拦截时自动降级切备用通道（例如邮箱被拦截时切 12377 客户端或公众号或热线），不转向非官方通道。

### 反伤与协同

反伤触发条件：监测层确认遭到打号/点号/炸群/人肉等恶俗攻击，且取证层已拿到真实证据。

反伤流程：接招→取证→装弹→发射，与 CICCS 五步闭环的"利用"与"反馈"环节对齐。

多群追加反伤（可选模块）：移植追加论至存护侧，对方攻击你→反向检索对方所在公开群→多群叠加举报→多平台并发发射。该模块仅使用公开可检索信息，不社工非授权数据。

协同接口：
- 反伤触发时通知虚无侧全频道频带阻塞干扰同步启动干扰
- 存护未防住且账号被冻时，自动唤醒丰饶侧复活甲流程
- 接收同谐侧信息安全提供的目标画像，直接生成反伤弹药

## 五、防御与反伤的协同

防御不是孤立的，是 CICCS 五步闭环的"利用"环节前半段：

```
攻击发生
  ↓
防御层响应（接口封锁+取证+预警）
  ↓
威胁评分 ≥ 中度？
  ↓ 是
反伤发射（多举报平台并发）
  ↓
通知虚无侧（全频道频带阻塞干扰同步启动）
  ↓
通知巡猎侧（超限卫兵按威胁等级选火力）
  ↓
账号被冻？
  ↓ 是
丰饶侧复活甲启动
```

防御做在前，反伤做在后。防御降低损失，反伤放大代价。两者合一才是完整的存护。

## 六、浏览器插件技术约束

Chrome 扩展采用 Manifest V3。MV3 要求：后台页面替换为事件驱动的 Service Worker，禁用持久化运行；网络请求拦截改用 declarativeNetRequest 声明式规则，不可使用阻塞式 webRequest；所有代码必须本地打包，禁止远程代码执行；权限需拆分为 host_permissions 精确声明；存储统一使用 chrome.storage 异步 API。

网安智盾 crx 据此定位为：多举报平台表单的辅助填充工具。
- 在 12377 官网举报页等合规页面，读取本地证据包（标准弹药 JSON），自动填充表单字段
- 通过 chrome.storage 持久化配置
- Service Worker 事件驱动，不持久化运行
- 不拦截、不篡改、不监听用户浏览流量
- 不请求与举报无关的 host 权限
- 不执行远程代码

## 七、移动端技术约束

Android 端使用 NotificationListenerService 做通知监听，MediaProjection 做录屏。

合规约束（参照 Android 与厂商规范）：
- BIND_NOTIFICATION_LISTENER_SERVICE 权限在 AndroidManifest.xml 中声明，用户通过专用设置页显式授权
- 申请权限时同步告知权限申请目的，目的明确且易于理解
- 用户拒绝或撤回授权时，App 不强制退出或关闭，不影响与此权限无关的功能
- 不存储或上传通知内容
- 提供关闭监听的选项
- 仅监听必要应用
- 录屏同理：用户显式授权，用途在隐私政策中披露，可随时关闭

## 八、性能要求

- 接口封锁响应：攻击检测到自动封锁完成，≤ 5 秒
- 取证固化：攻击触发到证据包生成，≤ 5 秒
- 预警弹窗：攻击发生到用户看到弹窗，≤ 3 秒
- 反伤发射：用户点确认到多通道并发提交完成，≤ 30 秒（不含平台审核时间）
- 误报率：≤ 1%（正常社交行为不被误封锁）
- 资源占用：PC 端常驻内存 ≤ 200MB，CPU 峰值 ≤ 15%；APK 端常驻内存 ≤ 80MB
- 截图分辨率不低于 1080p
- 录屏保留触发前后各 30 秒
- metadata.json 完整
- 并发通道至少支持 3 通道同时发射，备用通道自动补位

## 九、红线

- 不改包、不爆破、不逆向工程
- 不爬非授权数据，不社工无关人员
- 不伪造证据，不诬告陷害（严格遵循举报需真实、客观，不得诬告陷害）
- 不对非恶俗目标使用，仅用于反制恶俗攻击
- 反伤弹药必须基于真实攻击证据，类别选择须与 12377 举报专区对应，不得重复提交举报内容
- 不把用户零代码误解为开发零代码：开发端写代码，交付给用户的成品零代码使用
- 恶俗拦截某一通道时，软件自动降级切备用官方通道，不得因此转向黑产通道
- NotificationListenerService 获取的数据仅在本机处理，不传输到外部服务器；用户可随时撤销授权；拒绝授权不影响其他功能
- 接口封锁仅使用平台提供的隐私/安全设置项，不通过改包/逆向绕过平台限制
- 虚拟化隔离仅使用合法虚拟机/模拟器/备用设备，不进行设备指纹伪造
- 取证仅保存与攻击相关的证据，不窃取无关人员的隐私数据
- 自动封锁动作可逆，用户一键恢复
- 威胁评分算法透明，用户可在 config.ini 调整阈值
- 所有防御动作均在用户设备本地执行，不上传用户数据到外部服务器
- 防御对象仅为恶俗攻击；非恶俗目标触发时不自动封锁、不取证、不反伤

## 十一、与 CICCS 体系协同位置

网安智盾在 CICCS 六命途中的位置：

```
信息安全（同谐·情报）输出目标画像
  ↓
网安智盾（存护·防御反伤）接收并装弹
  ↓
全频道频带阻塞干扰（虚无·压制）同步启动
  ↓
超限卫兵（巡猎/毁灭·火力）按威胁等级选择
   巡猎模式点杀或毁灭模式面杀
   危险性巨大的涉及政治的反动恶俗组织启用屠龙咒
  ↓
复活甲（丰饶·治疗）全程待命，账号被冻时启动复活
```

网安智盾是这条杀伤链中"存护"那一环的执行体。其独特价值在于多举报平台编排能力——把 12377 官网、网络举报 APP、微信公众号、微博私信、12377 热线、jubao@12377.cn 邮箱、各地网信办、公安部网络违法犯罪举报网站等多个官方合规通道聚合为一个统一发射矩阵。对方可以拦截其中一个通道，但很难同时拦截所有通道；通道健康探测与自动降级保证反伤火力在任何单点干扰下仍能维持输出。

没有网安智盾，CICCS 攻强守弱；有了网安智盾，攻防对称。
